# 축제 QR 참여 플랫폼 (v2)

축제 현장에 QR을 한 번 설치하고, 서버에서 각 QR의 **모듈**만 바꿔 여러 콘텐츠로 운영하는 구조.
v1(QR 보물찾기 시범운영, 2026.10.26~27)의 데이터와 그대로 호환됨.

## 구성

| 위치 | 파일 | 역할 |
|---|---|---|
| Apps Script | `Code.gs` | 서버. 스캔 판정, 점수, 관제·분석 API |
| Apps Script | `Admin.html` | 관제 대시보드 (`…/exec?page=admin`) |
| GitHub Pages | `config.js` | 서버 주소 2개(시범운영·축제). 주소는 여기만 고침 |
| GitHub Pages | `portal.html` | 포털 (참여·자랑대회·공개 현황·순위 입구) |
| GitHub Pages | `index.html` | 참가자 화면 (QR 스캔 → 결과). `?s=fest`면 축제 서버 |
| GitHub Pages | `contest.html` | 자랑대회 (사진 올리기·투표) |
| GitHub Pages | `status.html` | 공개 현황 (닉네임 없는 집계 지도) |
| GitHub Pages | `rank.html` | 공개 순위판 |
| 구글 시트 | 설정·QR·참가자·기록·추첨·퀴즈·코스 탭 | 데이터 저장소 |

## 모듈

| 모듈 | 찍으면 | 점수 |
|---|---|---|
| 보물 | 회차(변경주기)마다 랜덤으로 일부 QR만 보물. v1과 동일 | 발견 1점 |
| 퀴즈 | 퀴즈 탭의 문제가 뜸. 1인 1회 응답, 현장에서 찍은 사람만 응답 가능 | 정답 = 퀴즈점수 |
| 코스 | 같은 코스명 QR을 모두 찍으면 완주 (순서 무관) | 완주 = 완주점수(1회) |
| 안내 | QR 탭 '내용' 칸의 안내문을 보여줌. 운영시간 밖에도 열림 | 없음 |
| 자랑대회 | 인증 QR을 찍은 사람이 사진 업로드 → 운영자 승인 후 공개 → 1인 하루 n표 투표 (대회·사진·투표 탭) | 없음 (득표 순위 별도) |

QR 이미지에는 거점 번호(`?qr=Q-01`)만 들어가므로 모듈을 바꿔도 다시 인쇄할 필요 없음.
단, 운영 중에 **보물 모듈 QR 수를 바꾸면 그 시점부터 회차별 보물 조합이 달라짐**.

## v1 → v2 적용 순서

1. 구글 시트 → 확장 프로그램 → Apps Script
2. `Code.gs` 전체를 새 `Code.gs`로 덮어쓰기, `Admin.html`도 새 파일로 덮어쓰기 (`Index` 파일은 그대로)
3. 편집기 위 함수 목록에서 `upgradeV2` 선택 → 실행 (처음 한 번 권한 승인)
   - QR 탭에 모듈·코스·내용·X·Y 열, 설정 탭에 새 항목, 퀴즈·코스 탭이 생김
   - 기존 기록·참가자·추첨 데이터는 건드리지 않음. 여러 번 실행해도 안전
4. 배포 → 배포 관리 → 연필 → 버전: **새 버전** → 배포 (주소 유지)
5. GitHub 저장소의 `index.html`, `rank.html`을 새 파일로 교체 (API_URL은 기존 주소 그대로 들어 있음)

## 설정 탭 새 항목

| 항목 | 기본값 | 설명 |
|---|---|---|
| 행사명 | QR 보물찾기 | 참가자 화면·순위판·관제 제목 |
| 좌표계 | 도면 | `도면`: 도면 이미지 기준 X·Y(0~100, 왼쪽 위 0) / `위경도`: X 경도, Y 위도 (OSM 지도) |
| 도면이미지 | (빈칸) | 도면 모드 배경. GitHub 저장소에 png를 올리고 Pages 주소를 넣음 |
| 도면크기 | (빈칸) | 도면이 덮는 실제 크기(m), 예 `60x20`. 이동속도 이상 검사에 씀 |
| 퀴즈점수 / 완주점수 | 1 / 3 | |
| 최소스캔간격 | 5 | 서로 다른 QR을 이 초보다 빨리 연달아 찍으면 확인 대상 |
| 최대이동속도 | 4 | 거점 사이 이동이 이 m/s보다 빠르면 확인 대상 (좌표 필요) |

## 관제 화면 탭

- **현황**: 거점별 오늘 스캔·점수, 팀·개인 순위, 학생증 확인
- **지도**: 거점별 이용량(스캔·방문자·점수) 원 크기 + 이어서 이동한 동선 선 굵기. 날짜·시간 필터
- **거점 관리**: 지도를 눌러 좌표 찍기, 모듈·코스·안내문 변경, 거점 추가
- **분석**: 시간대별 스캔(날짜 비교), 거점별 이용과 다음 이동, 퀴즈 정답률·코스 완주율, 이상 패턴, CSV·GeoJSON 내보내기
- **추첨**, **QR 인쇄**: v1과 동일

## 데이터·개인정보

- 수집: 닉네임, 소속(팀), 4자리 번호의 해시값. 실명·연락처·학번은 요구하지 않음 (시범운영 때 닉네임에 실명·학번을 적은 참가자가 있었으니 참가 화면에서 안내할 것)
- 내보내기 CSV는 닉네임을 빼고 참가자를 익명 코드로 바꿈
- 이상 패턴은 자동 실격이 아니라 운영자 확인 대상 표시
- 이 저장소는 공개이므로 시트 데이터·관리자코드·랜덤시드를 올리지 말 것

## 알려진 한계

- 구글 시트 기반이라 동시 접속이 많으면 응답이 느려짐 (시범운영 때 타임아웃 경험). 축제 실운영 규모에서는 DB 기반 서버로 옮길 필요가 있음
